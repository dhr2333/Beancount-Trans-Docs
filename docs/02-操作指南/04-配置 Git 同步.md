**将您自己的账本与平台同步**：账本始终在您自己手里（或在本地、或在远程仓库），平台只是能看到并使用它——~~用于 Fava 报表、Copilot 分析~~，以及您分享给他人后的只读访问。 %% 能结合平台的账户/标签上下文为账本分析提供更多的维度；支持移动端随时随地进行决策前分析或条目记录； %%

## 一、适用场景与前提

适用：

- 账本已经在你自己的 Git 远程仓库里，想在平台上继续看报表、用 Copilot 分析；
- 习惯用编辑器 + Git 管理账本，希望平台也能读到最新内容；
- 想把这份账本就着平台分享给他人：见 [分享账本给他人](https://trans.dhr2333.cn/docs/%E6%95%99%E7%A8%8B/share-ledger)。

前提：你有一个可访问的 Git 仓库、并能向它推送（下面的「关联已有远程」可以让你继续使用现有的仓库）。

> 如果您还没有账本，可以先按 [快速入门](https://trans.dhr2333.cn/docs/%E6%95%99%E7%A8%8B/quick-start) 上传账单并解析，不必使用 Git 同步。

## 二、启用 Git 同步

### 1. 进入设置

1. 登录平台，悬停右上角用户名，选择 **「个人设置」**；
2. 打开 **「Git 同步」** 标签页。

### 2. 选择仓库创建方式

| 方式         | 适合谁                        | 说明                                         |
| :--------- | :------------------------- | :----------------------------------------- |
| **基于模板创建** | 刚开始用 Beancount、想用标准结构      | 平台按标准模板建库，包含目录结构与账户体系，开箱即用                 |
| **空仓库创建**  | **已有账本的用户**（页面标注为「推荐迁移用户」） | 建一个空仓库，等您把现有账本推上来                          |
| **关联已有远程** | 账本已经在自己的 Git 远程仓库上         | 关联你现有的仓库；平台生成**只读拉取**用的密钥，推送仍使用你自己的 Git 凭据 |

### 3. 下载 Deploy Key 并配置 SSH

1. 在页面点击 **「下载 Deploy Key」**，得到一个 `.pem` 私钥文件；
2. 按页面提示配置 SSH：给密钥设置权限，并把密钥写进 `~/.ssh/config`。

### 4. 克隆仓库到本地

**直接复制页面给出的克隆命令**（形如下面这样）：

```shell
git clone <页面给出的 ssh_clone_url> Assets
```

## 三、把本地账本放进仓库并推送

1. 把您的账本文件放进刚克隆出来的仓库目录（主文件 `main.bean` 放在**仓库根目录**）；
2. 提交并推送：

```shell
git add .
git commit -m "更新账本"
git push origin main
```

若页面显示的分支名不是 `main`，以页面显示的为准。

3. 让平台拉取最新内容：默认由仓库的 **Webhook 自动同步**；也可以回到 **「个人设置 → Git 同步」** 点 **「立即同步」**。

您应看到：打开 **「平台账本」**（Fava）能看到你刚推送的账户与交易。

## 四、目录与主文件约定

- `main.bean` 必须放在**仓库根目录**（平台固定以仓库根目录下的 `main.bean` 作为账本入口）。
- 平台默认模板的 `main.bean` 里有一行 `include "trans/main.bean"`；`trans/` 是**平台的解析产物**（账单解析结果），被 `.gitignore` 忽略、不进 Git。
- 想同时在平台上看到**您自己的账本**与**平台解析出的账单**，建议沿用默认模板的结构（`main.bean` 在根目录、且包含 `include "trans/main.bean"`）；去掉这一行后，平台的解析结果不会显示在你的账本里。

<details>
<summary>模板的目录结构大致长什么样</summary>

- `main.bean`：主账本入口（包含各条 include）
- `account/`：账户定义
- `20XX_template/` 等：按年份组织的交易记录
- `document/`：通过 Fava 上传的附件
- `depreciation.bean`：折旧记录
- `trans/`：**平台管理**的解析产物（被 `.gitignore` 忽略）

## 五、同步行为与边界

| 行为 | 说明 |
| :--- | :--- |
| 同步方向 | **平台只拉取、不推送**您的账本；同步以**远程仓库为准** |
| 与解析产物的关系 | 同步时会先备份并保留 `trans/`，平台解析结果不会被覆盖 |
| 自动同步 | 仓库默认配置 Webhook，推送后平台自动同步 |
| 手动同步 | 在「Git 同步」页点 **「立即同步」** |
| 取消同步 | 清除 Git 引入的账本内容并暂停自动拉取，**保留 `trans/` 解析结果** |
| 下载解析结果 | 在该页可把 `trans/` 打包下载（ZIP） |

## 六、常见问题

**Q1：为什么 `trans/` 不进 Git？**

避免冲突：解析结果由平台持续更新，纳入 Git 容易产生冲突。用 `.gitignore` 忽略它，需要时用「下载解析结果」获取。

**Q2：推送后平台没有自动同步？**

点 **「立即同步」** 手动触发即可；同步状态与错误信息会显示在设置页面。

**Q3：什么时候需要重新生成 Deploy Key？**

密钥遗失或泄露、更换设备，或平台提示密钥失效时。重新生成后按提示下载，并更新本地 SSH 配置中的密钥路径。

**Q4：本地修改会和平台解析结果冲突吗？**

不会。平台单向同步（只拉取、不推送），且 `trans/` 不进 Git，两者互不干扰。

**Q5：仓库大小有限制吗？**

有。具体阈值以平台提示为准。建议定期归档历史年份的账本，避免提交图片、PDF 等大文件。

**Q6：可以在多台设备上使用同一个仓库吗？**

可以。各设备配置同一个 Deploy Key 并克隆仓库，编辑后推送，其他设备执行 `git pull` 获取最新内容。
